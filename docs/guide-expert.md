# Guidelines: reference for developers

`meerkat guide` checks the current change against a short list of working rules for AI-assisted coding. It is read-only (git diff, git log, the text of changed files) and advisory: it prints and records findings and never changes the exit code of `verdict`, `gate` or any other command. Exit 0 always, 2 for a usage error (unknown option, unknown `--explain` id).

```
meerkat guide [folder] [--base <ref>] [--json]
meerkat guide --explain <id> [--json]
```

The change is the same one `meerkat gate` sees: committed changes since the merge base with `main` or `master` (or `--base`), plus uncommitted and untracked files.

## The guidelines

| Id | Fires (ADVISORY) when | NOT CHECKED when |
| --- | --- | --- |
| `g-small-change` | more than 15 files or 800 changed lines | nothing changed |
| `g-tests-with-code` | code under `lib/` or `src/` changed and no test file did | no such code changed |
| `g-no-secrets` | a changed file holds a token or private key shape (the patterns in `thorough/redact.mjs`) | no changed text file |
| `g-no-machine-paths` | a changed text file holds a Windows user-folder or `/home/` path | no changed text file |
| `g-commit-message` | the latest commit message is empty, one word, or starts with `wip` or `fix stuff` | the branch has no commit of its own |
| `g-verify-before-done` | no run is recorded for the project, or the newest one is older than the last edit | nothing changed |
| `g-no-generated-edits` | a file with `generated by` in its first 3 lines changed and the generator it names did not | no changed file says it is generated |
| `g-docs-with-behaviour` | `lib/cli.mjs` changed, or a changed flag is mentioned in README or `docs/`, and no docs file changed | neither happened |

## Turn one off for a project

In `meerkat.config.json`:

```json
{
  "guidelines": { "disable": ["g-commit-message", "g-docs-with-behaviour"] }
}
```

A disabled guideline is still listed, as `NOT CHECKED ... turned off in meerkat.config.json (guidelines.disable)`, so the choice stays visible in the log. Unknown ids in the list are ignored.

## Reading the output in a CI log

```
ADVISORY    g-tests-with-code  code changed (lib/a.mjs) and no test file changed
NEXT        g-tests-with-code  Add or update a test that fails without your change, then run it.
PASS        g-no-secrets  4 files scanned
NOT CHECKED g-commit-message  no commit of its own on this branch yet
ADVISORY    guide  1 advisory finding (exit code unchanged)
```

Every line carries the rule id in its second column, so `grep g-tests-with-code` finds the finding and its next step. The last line is the count. For machines use `--json`: `{ schema, advisory, comparing, guidelines: [{ id, status, detail, fix }] }`. The newest result is also written to `guide/<project>.json` under the Meerkat log folder (beside `runs/`, so it never counts as a run).

To make a CI job fail on advisories anyway, read the count yourself, for example `meerkat guide --json | node -e "..."`; Meerkat itself will not.

## Add a guideline

1. Edit `lib/guidelines.mjs`: add one object to `GUIDELINES` with `id` (`g-...`), `rule`, `why` (one sentence), `how` (how it is checked from git), `fix`, and `run(ctx)` returning `{ status: 'PASS' | 'ADVISORY' | 'NOT CHECKED', detail }`. `ctx` has `files`, `lines`, `committed`, `subject`, `read(file)`, `codeFlags`, `docText` and `lastRunDir`. Keep it read-only and fast.
2. Add a fixture test to `tests/guidelines.test.ts`: one bad change that makes it fire and one good change where it stays quiet.
3. Add a row to the table above, and run `npx vitest run tests/guidelines.test.ts lib/help.test.ts`.
